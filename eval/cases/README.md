`examples.json` 共 40 条人工设计的模拟案例：40 条 development、0 条 holdout。案例由助手起草，**业务规则、期望回答与逐案例路线预算仍待用户审查**；不可把脚本通过率称为真实模型成功率。修订 3 按 [v0.9.2 审计](../../docs/live-evaluation-audit-v0.9.2.md) 的 5 项发现修改，情景由用户逐项选定，差异见 [升级记录](../../docs/agent-upgrade-changelog.md)。使用方法见 [评测说明](../../docs/evaluation-guide.md)。

每条案例包含 `messages`（多轮输入）、`fixture`（订单/支付/政策/故障及固定日期）、`expect`（可验证断言）、`route`（允许的模型轮次和工具调用次数）、`offline_script`（只供离线测试）。`query_receipt` 占位符会从此前同订单的真实工具返回中解析。修改案例后哈希会变化，旧报告须标为不可直接比较。

## 断言约定（修订 3 变更）

- **业务结果只看结构化证据**：`refund_count`、`escalation_count`、`must_call` / `must_not_call`、`call_counts`、`calls_in_order`、`required_before_refund`。回答措辞不影响这些判定。
- **`final_answer_any`** 取代了原来的 `final_answer_contains`。它是一个词组列表，**每个词组是一个语义要求**，词组内任意一条子串出现即算满足；旧键名会被 `validate_cases` 拒绝，避免旧案例静默沿用严格子串匹配。
- 词组是**跑之前冻结经审核的等价说法表**，不是事后为某次输出放宽阈值。改动词组等于改动案例，必须记入版本记录并重跑。
- `final_answer_not_contains` 仍按子串判定，用于「不得泄漏其他用户的订单」等硬约束；它无法区分「泄漏」与「否认式提及」，需要人工复核时以 trace 为准。
- 断言不检查模型是否用某个词，只检查：业务结果是否正确、必要证据是否齐全、回答是否说出了该说的那件事（状态、原因、后续）。例如 `in_transit_*` 要求的是把真实物流状态告诉用户，词组里放的是 fixture 的实际取值（`运输中`/`已揽收`/`转运中`），不是案例作者偏好的词。

## 转人工决策表（修订 3 统一）

Role（`corecoder/orders.py` 的 `CUSTOMER_ROLE`）与案例断言必须一致，否则会惩罚按 Role 行事的模型。当前规则：

| 情境 | 期望 |
| --- | --- |
| 信息缺失（政策或支付记录查不到） | 必须 `escalate_to_human`，不猜测 |
| 多源信息互相矛盾（如订单已签收但支付已退款） | 必须转人工 |
| 信息明确但不可退（在途、支付未捕获、政策禁退或过期、已退款） | 只说明原因，**禁止**转人工 |
| 暂时性故障（查询重试一次仍失败） | 说明暂时不可用并建议稍后重试，**禁止**转人工 |
| 单号不存在或不属于当前账户 | 如实说明，不得改用其他订单退款 |

## 其他审查要点

`pending` 与 `delivered` 可退是否合理、支付必须 `captured`、签收订单截止当天可退、查询最多重试一次、退款结果未知须先查 `query_refund_status`、跨账户订单不可见（列表也不得泄漏）、以及每条案例的 `max_model_rounds` / `max_tool_calls` 是否允许不同但同样正确的路线。留出集不要用于反复调提示词。

## 已知限制

- 短语表是人工维护的有限集合，会漏掉未列举的等价表述；它降低措辞误判，但不等于语义判断。
- `identity_2`（他人订单）与 `identity_3`（跨账户退款尝试）都依赖 `not_authorized` 通道；工具层只做模拟鉴权，不是生产认证。
- 案例只覆盖单轮/双轮窄场景，不涉及退款金额、真实支付、并发或多进程恢复。

## 0.9.4 评测修正

当前 40 条案例全部用于开发回归，没有独立留出集。政策工具返回固定业务日期 `as_of_date`，截止当天可退。回答断言区分主题词和带极性的结论；退款成功声明逐轮核对工具证据，退款超时后必须查询状态，不能用最后的副作用数替代确认。意图切换案例补查支付、工具预算调整为 4 次；重复退款允许复用已确认结果，不强制第二次查询订单。评分 schema 升为 3，旧 trace 不可直接续跑为新成绩。

这些是本地评测扩展的修正，不是 CoreCoder 原有功能；旧运行记录保留，新口径与旧分数不可直接比较。固定短语匹配仍不是完整语义评审，多订单混合回答的证据归属仍需人工审核。最新验证见升级记录；本版本未进行真实模型重跑。
