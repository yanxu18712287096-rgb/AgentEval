# Coding 策略候选 trial-1 成对回归（2026-10-02）

结论：**拒绝候选，不激活**。[严格比较产物](../eval/runs/repository-paired-trial-1-final-20261002/decision.json)显示 `verdict=reject`、`blocking_reasons=[]`，H03 第 1、2 次重复出现基线通过而候选失败。全部 6 个冻结仓库任务各重复 3 次，两组共 36 次真实模型运行，均有独立 Trace、补丁、测试与用量记录。最终回答的语义质量尚待人工复核；此处只比较客观测试。

## 设计与产物

- 无 Skill 基线与 [trial-1 候选](../eval/runs/repository-dev-baseline-rescore-v3-20261001/candidate-trial-1.json)使用同一 `kimi-k2.7-code`、Runtime、案例、容器镜像和评测器，只变更注入的 Skill。开发集 D01–D03 与留出集 H01–H03 各 3 次重复，执行顺序交替。留出集没有进入失败归因或候选生成。
- [完整实验](../eval/runs/repository-paired-trial-1-final-20261002/experiment.json)封存 36/36 次结果。运行曾在 H03 的一次基线中因 `APIConnectionError` 中断；[原始中断实验](../eval/runs/repository-paired-trial-1-20261001/experiment.json)与[第一次续跑](../eval/runs/repository-paired-trial-1-resumed-20261001/experiment.json)保留。`scripts/resume_coding_pair.py` 校验 manifest、receipt、运行产物和完整指纹，分别复用前 20 和 35 次有效运行，在新目录重试末尾断线运行；两次错误运行不计入最终 36 次。续跑来源见最终目录的 `resume-provenance.json`，可逐层追溯。
- 严格比较器核对 36 次结果、每组配置/代码/案例指纹、策略哈希和用量，无阻塞性校验错误。旧开发集基线 7/9 属于另一次随机实验，不能与此处候选 8/9 直接比较；本报告仅用本轮同时执行的 5/9 基线作对照。

H03 的模型行为提示：这条面向多资源原子性的长 Skill 在无关的预订改期任务上可能增加探索与手工检查，但小样本不能单独证明因果。它的两项客观回归已触发预设拒绝规则，因此不因开发集提升而接受。候选未进入默认 Coding Role；若继续改进，应从这次留出集失败做新一轮开发证据，并另备真正未触碰的留出集，避免把 H03 反复用于调参。

案例均为小型合成仓库，留出集由本项目编写并在执行前冻结，不能据此宣称大型真实仓库的泛化效果。
