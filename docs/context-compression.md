# v0.15.0 上下文压缩流程

本模块压缩的是将要发送给模型的 `Agent.messages`，不是评分证据。评测运行中的完整工具请求与结果仍按原样写入 `TraceRecorder`；普通未启用 trace 的交互只在当前 `ContextManager.original_groups` 中暂存被投影的原始工具组，**跨进程 Session 尚不保存这些原始组**，不能把压缩后的 Session 当完整审计记录。

## 执行顺序

1. 在模型调用前，以及完整工具轮次返回后检查上下文。先验证每条 assistant `tool_calls` 消息紧跟且只跟随其全部结果；缺失、重复、错 ID 或孤立 tool 消息时不压缩，trace 记录跳过原因。
2. 超过 50% 预算时，在消息副本中选择足够旧的完整**只读**工具调用组。仅对可解析、可完整提取有界 JSON 标量的长结果做结构化投影；投影保留调用/结果 ID、查询凭据、退款状态、错误码等原值及来源 SHA-256。写操作与无结构长文本不做盲目截头截尾。原始组暂存在内存中；评测模式由独立 trace 永久保存。
3. 仍超过 70% 且历史足够长时，总结旧的完整对话段，附加确定性工具证据台账和近期用户原话。台账过大、工具结果无法安全提取时放弃该层。超过 90% 可尝试更激进的旧段折叠，但执行同样检查。
4. 提交前再次校验 tool call/result 配对、关键事实文本仍存在、token 估算确实下降。任一条件失败就丢弃副本，原消息不变。成功或跳过均在有 trace 时写入 `context_compression` 事件；成功事件含层级、前后 token 估算和原始组哈希。

这不是“摘要绝对正确”的证明：关键事实校验为确定性的字段/值保留检查，不能理解所有自然语言含义；模型生成的叙述性摘要可能有语义偏差。对于不能安全提取的长文本，策略宁可保留原文；极端情况下可能仍触及模型上下文上限。普通 Session 的持久化和精确 tokenizer/模型反馈仍是后续工作，不能宣称已解决。

## 验证口径

单元测试覆盖并行双工具组、乱序/缺失/孤立结果、查询凭据与退款成功证据保留、坏摘要回滚、无结构长文本跳过，以及 trace 压缩事件。脚本订单案例回归只验证运行协议和既定规则，不代表真实模型在长对话中的业务效果。后续应加入长对话真实模型对照：压缩开/关固定案例与模型配置，比较业务通过率、安全错误、工具轮次、token 和耗时；安全指标不得退步。
