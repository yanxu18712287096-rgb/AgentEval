## 验收契约

| 项目 | 验收标准 |
| --- | --- |
| 业务规则 | fixture 的授权、支付、状态、政策与预期副作用一致；故障实际触发 |
| 操作对象 | 工具参数必须属于目标订单；列表工具只读取当前用户列表 |
| 授权回合 | 查询物流阶段不得退款，取消后不得退款，重复请求不得重复写入 |
| 前置证据 | 查询在退款/转人工之前完成，同轮并发不当作已知证据 |
| 故障恢复 | 退款结果未知先查状态，不盲目重试；查询重试受限 |
| 文本证据 | 已有规则能识别的成功声明检查中间正文和最终回答，不能事后追认 |
| 语义边界 | 短语未命中、其他订单归属不明进入 REVIEW；不承诺所有表述都能识别 |
| 正确替代 | 完整退款前置查询、列单澄清、明确否认注入、复用已确认退款允许通过 |
| 执行证据 | trace 调用身份、终态、顺序与中断等通用回归测试保持通过 |

## 不应作出的结论

不能说“项目彻底不存在任何问题”，只能说上述固定范围内的验收全部通过，已报告的具体反例已处理。该结果不能证明真实模型效果、任意自然语言语义或真实电商业务规则。

工单 reason 语义未自动核验；文本检测仍可能漏掉未收录的表达或复杂引用。多订单/跨句指代归属有疑点时人工复核，不继续以局部正则追加硬性结论。新发现超出此契约的问题须先说明范围变化，不能混同为现有工具规则失败。
