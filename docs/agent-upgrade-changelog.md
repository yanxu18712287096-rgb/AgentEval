## 0.16.0 — 2026-09-30

### 相对 0.15.0

- 新增独立 `corecoder.coding_eval`：将原有 CoreCoder Agent 接到小型 coding 评测管线，不改订单、校园和 SaaS 场景的评分口径。每次运行重新构造临时仓库工作区；文件工具限定在工作区内，Shell 和评测器的公开/隐藏测试在禁网、只读挂载、非特权 Docker 容器中执行。Docker 缺失时失败，不回退到宿主 Shell。
- 新增 8 条人工编写微型 Python 缺陷案例，开发集 4 条、冻结 holdout 4 条。每例有公开检查、独立隐藏检查和允许改动范围；隐藏测试在 Agent 结束后才挂载，模型工具不可见。结果评分使用测试退出码、补丁范围、运行完成性和工具调用/结果配对；回答语义仍标记待人工复核，不把测试通过包装为完整语义正确。
- 新增逐例 `trace.jsonl`、`patch.json`、`test-results.json`、`result.json` 与整组 `scorecard.json`，记录 Runtime/模型/Role/案例/隐藏测试/镜像指纹、工具/模型轮次、token 和耗时。`--resume` 只复用指纹及三个产物哈希一致的完整运行；`--baseline` 对指纹相同的行做严格对比；真实模型请求支持跨案例限速与 429 有界重试。新增 `corecoder.coding_rescore`，对哈希校验过的历史补丁在容器中重新运行当前测试，单独标记历史产物重评分。
- 相比 v0.15.0 的业务场景评分，此版主要解决代码产物的隔离、执行性断言和回归证据。未实现任意外部 coding Agent 适配、跨进程 checkpoint/恢复、异步 Branch Agent、LLM Judge 或大型仓库基准；不应把 XiaoBa-CLI 的执行型 Runtime 误认为本项目的评测结果。
- 验证：`RUN_DOCKER_CODING_TESTS=1 venv311/bin/python -m pytest -q` → **492 passed**（含全部 Docker 集成用例）。8 条案例的初始公开测试均通过、隐藏测试均检出缺陷，容器 Shell 无法改写工作区文件，工具结果身份/顺序受到校验，并验证“先工具报错后修复成功”只计效率告警。一次 `kimi-k2.7-code` 单例端到端 smoke：CODE-01 **1/1 客观测试通过**，6 轮模型、6 次工具、4,254 token；这是开发集单例，不代表总体效果。
- 完整 8 条 × 3 次真实模型运行原始规则 **21/24**；审计发现 CODE-03 两次被越界隐藏断言误判、CODE-05 一次被已恢复工具错误误判。原 trace/报告不覆盖；按修正口径对相同历史补丁重新执行测试为 **24/24 客观通过**，没有新模型请求。该结果只说明这组小型合成任务的客观检查；答案语义待人工复核，holdout 已被查看，不再作为未触碰盲测。成本及逐例证据见 [审计报告](coding-evaluation-live-review-v0.16.0.md)。
- 案例和使用方法见 [评测指南](evaluation-guide.md)；已交付边界见 [v0.16.0 面试展示版说明](coding-evaluation-v0.16.0.md)，更大范围但未实现的目标单独留在 [coding 目标规格](coding-evaluation-final-spec.md)。原始运行产物在本地 `eval/runs/`，该目录默认被忽略，不会自动随项目提交。

## 0.15.0 — 2026-09-30

### 相对 0.14.0

- 重构 `ContextManager`：压缩前后验证 assistant 工具调用与全部 tool result 的一一对应；第一层由逐条截短改为对完整、较旧的只读调用组做结构化 JSON 投影，保留调用 ID、精确有界字段与源哈希。写工具结果、不可安全解析的长文本不做盲截。第二/三层历史摘要附确定性工具证据台账及近期用户原话。

- 验证与限制详见 [压缩流程](context-compression.md)。新增并发工具组、错误配对、退款状态、坏摘要与无结构文本的测试；未通过真实模型长对话对照证明业务效果。普通 Session 仍只保存压缩后的消息，精确 tokenizer 与跨进程原始组归档未做。本版未改变订单/故障场景规则或案例断言。
- 验证：`venv311/bin/python -m pytest -q` → **469 passed**；订单 38 条 × 1 次离线脚本回归 → **38 PASS、38 条预设路线达标**，见 `eval/runs/v0.15.0-orders-scripted-compression-check/`。该常规短案例运行基本未触发压缩，只验证无回归；压缩边界由专门单元测试覆盖，尚无真实模型长对话收益数据。

### 已知限制与后续依据

- 尚未运行真实模型评测；`live` 模式需要用户配置模型和密钥，会发生 API 调用。不能将 scripted 的 10/10 写成真实模型效果。
- 退款规则是教学模拟，案例待用户审查；仅 10 条核心案例，无真实客户数据或留出集，不宣称泛化性能。
- 最终回答只做字面包含检查，不能验证完整语义真实性；需要人工审核或后续单独引入语义评测。
- 业务超时是工具返回错误的模拟，不是通用工具进程超时控制。原生子 Agent 的嵌套 trace、跨进程恢复、自动修复与异步多 Agent 不在本版本范围内。
- token 报告目前只累计主对话模型响应，不含可能的压缩摘要调用；不报告美元估算。
