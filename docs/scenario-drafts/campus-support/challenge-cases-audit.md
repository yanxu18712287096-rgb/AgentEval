# 第二批 6 条挑战案例：逻辑审查

日期：2026-09-30；场景版本 `campus-support@1`；案例文件 [campus-support-challenge.json](../../../eval/cases/campus-support-challenge.json)。六条均为 development，单独运行，不混入首批 12 条分母。资料仍为 0.2.0-draft，Role 不含 Skill；旧案例和旧运行产物均保留。

| 案例 | 新的判断难点 | 静态核查结论 |
| --- | --- | --- |
| CS-H01 | 用户声称 12 MiB PDF，系统报 `UNSUPPORTED_FORMAT`，同时有上传故障公告 | 按文档，大小/后缀本应合规，但不能据此证明文件内容或平台误判；公告仅解释 `SERVICE_UNAVAILABLE`。要求保留不确定性、追问有区分力的信息。 |
| CS-H02 | CSV `FAILED` 遇到 PDF `PROCESSING` 公告 | 公告明确排除 CSV，且两种错误状态不同。不能把同模块事件强行归因，也不把“CSV 可导出”误读为该用户此次导出已成功。 |
| CS-H03 | 09:35 的历史故障与 09:42 的当前状态 | U1 在 09:10 发布，可支持历史问题匹配；09:40 实际恢复的消息 U2 到 09:45 才发布。因此 09:42 不能确定“已恢复”或“仍未恢复”。 |
| CS-H04 | PDF 导出 17 分钟未完成，CSV 可用但作业仅收 PDF | 14:03 至 14:20 确为 17 分钟；PDF `PROCESSING` 与 U1 匹配。CSV 是平台可用格式，不是课程接受的替代提交格式。 |
| CS-H05 | 临时锁定期间用户已重置密码 | HELP-LOGIN-002 明确重置不提前解除锁定；17:05 早于页面预计 17:15 解锁。第二轮需复用第一轮证据，不能承诺精确时刻必然成功或代为解锁。 |
| CS-H06 | 第一次公告查询超时，第二次成功 | 故障配置仅影响本例第一次合法公告调用，第二次正常返回 U1；评分检查第二次请求在第一次超时结果之后，防止并发两次碰巧拿到不同结果充当“重试”。 |

每例含独立逐轮必需项、禁止项、真实工具证据和离线脚本。没有以固定 `final_any` 短语覆盖模型回答；语义正确性仍需复核。新案例不从旧 12 条抽取运行子集，因此可以直接用单独 JSON 跑；它们在本轮真实测试后也不应再称为未见过的 holdout。

初稿静态范围内未见资料、时间、用户意图和预期之间的硬性矛盾；真实运行暴露了 CS-H06 的查询时间限制过窄，已在 v0.12.2 修正并增加反例测试。6 条离线脚本执行结果均为 REVIEW、无硬性 FAIL，仅证明链路与结构化断言自洽。最终真实运行及人工辅助语义结论见 [复核报告](challenge-live-review.md)。如需再改案例，须提升案例版本并保留旧 trace，不直接覆盖运行结果。
