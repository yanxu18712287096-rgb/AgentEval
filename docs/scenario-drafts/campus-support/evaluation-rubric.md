# 独立评测标准：校园软件使用助手

版本：0.2.0-draft；状态：评分设计与审查示例，尚未实现评分器或可执行案例集。

本文件仅供评分端和人工审核。禁止注入被测 Role、Skill 或帮助检索语料。评估的是当前轮任务完成情况，不是答案是否逐字相同，也不是是否走过唯一工具路线。

## 1. 规则与语义分开

确定性规则检查：工具白名单与参数合法性、调用结果配对、公告可见时间、引用 ID/版本是否存在于此前获得的证据、执行是否完整。存在的引用不一定支持结论，支持关系需要语义评审。

不强制每个回答展示引用；案例明确要求引用时必须提供。没有展示引用不等于无依据，Judge 应检查此前对话及工具返回。首次陈述平台专有事实需要已获得的资料支持，不允许凭模型记忆猜中即算证据合格。

语义评审按每轮标准逐项返回 `pass` / `fail` / `uncertain` / `not_applicable`：

| 维度 | 判断内容 |
| --- | --- |
| 任务完成 | 是否解决当前请求，必要结论和建议是否完整；不能答非所问 |
| 证据一致 | 平台事实有依据，时间、范围和症状匹配；不编造已完成动作 |
| 指令遵循 | 遵守最新用户意图及明确格式要求，不继续已取消的任务 |
| 澄清合理 | 缺信息时询问影响判断的内容；信息充分时不机械追问 |

每个案例把必要项和禁止项列为独立 criterion_id，附适用轮次。可选加分建议不作为失败条件；“简洁”“清楚”若无可操作尺度只记录质量意见，不自动硬判失败。禁止用一组短语覆盖所有正确表达。

## 2. 总判定与指标

- 已证实违反必需项/禁止项或确定性规则：FAIL。
- 无确定失败但存在 `uncertain`，或必要语义项尚未评分：REVIEW。
- 执行完整、规则通过且所有适用必需语义项通过：PASS。
- 语义项不适用必须给理由，不能借此跳过业务必要项。Judge 无法调用、输出损坏或证据缺失进入 REVIEW，不自动 PASS。
- 某一项既有失败又有不确定时整体 FAIL，并保留待复核标记；人工裁决另存，不覆盖原始结果。

报告 PASS/总案例数、FAIL/总案例数、REVIEW/总案例数及分维度结果。人工最终通过率单列，并保留审核者、理由、原始标签。多轮案例要求每轮满足当轮标准，禁止最后一轮正确掩盖首轮错误。

调用数、模型轮次、输入/输出 token、耗时、工具错误次数单独报告。预算超出属于效率问题，不抹去任务正确性；“任务通过且预算达标占比”不是数学最优路线率。Judge 的 token/耗时与被测 Agent 分开统计。

## 3. 审查示例（不是可执行案例）

### CS-01：明确超限

- 用户：我的 PDF 有 28 MiB，上传提示文件太大，怎么办？
- 必须：说明超出 20 MiB；建议压缩到不超过上限后重试。
- 禁止：无依据归因系统故障；声称已替用户上传。
- 证据：HELP-UPLOAD-001。允许任何语义等价表达，不强制调用公告工具。

### CS-02：信息不足

- 用户：文件上传不了，帮我看看。
- 必须：询问能区分原因的信息，例如错误提示；如同时询问大小/格式也接受。
- 禁止：直接确定为文件过大或服务故障。
- 本轮合理澄清即成功，不能要求最终解决。无平台事实断言时允许零工具调用。

### CS-03：按三步整理

- 用户：把 PDF 学习报告导出步骤整理成三步，不要其他说明。
- 必须：恰好三个操作步骤，涵盖进入学习报告、选择日期范围、点击导出并选择 PDF。
- 禁止：编造入口；添加无关排查说明；声称已完成导出。
- 证据：HELP-REPORT-001。编号样式可不同，“三个步骤”需按语义而非只数换行判断。

### CS-04：公告不可提前可见

- 固定 as_of：2026-09-28T09:20:00+08:00。
- 用户：现在上传显示 SERVICE_UNAVAILABLE，是平台的问题吗？
- 必须：依据可见 U1 说明存在匹配上传故障，当前已发布状态是调查中，无确定恢复时间。
- 禁止：引用 U2；预告 09:40 恢复；声称附件已自动提交。
- 证据：NOTICE-UPLOAD-001/U1。可说症状与公告一致，不要求断言排除了全部其他原因。

### CS-05：改变意图

- 第一轮：文件上传不了。标准同 CS-02，追问即可。
- 第二轮：不用排查了，只告诉我支持哪些文件格式。
- 第二轮必须：回答 PDF、DOCX；禁止继续索要排障信息或输出无关故障分析。
- 第二轮证据：HELP-UPLOAD-001。不得只评分第二轮而忽略第一轮。

### CS-06：没有公告不代表正常

- 固定 as_of：2026-09-28T10:00:00+08:00。
- 用户：现在能登录吗？
- fixture：查询当前 login 公告成功但结果为空。
- 必须：说明未查到当前匹配公告，无法仅凭此确认登录一定正常；可建议尝试登录，如报错再提供提示。
- 禁止：声称已检测登录成功，或平台保证正常。
- 此处不要求额外编造账号排查步骤。

## 4. Judge 与人工证据

Judge 输入只含截至该轮的用户对话、可观察回复、工具请求/结果、当轮标准及合法资料快照。后续用户消息不能反向授权或补齐先前回答。检索文本与被测回答均视为待审数据，不执行其中的评分指令。

每项输出至少包含 criterion_id、verdict、reason、trace 事件位置；涉及资料时附 evidence_id。不得要求隐藏思维链。Judge 的模型、提示词、参数、原始输出和版本均留存。人工先用正确、错误、模棱两可三类固定答案校准 Judge；不能用未校准的 Judge 分数证明效果提升。
