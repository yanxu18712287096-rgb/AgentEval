# 无 Skill 基线准备方案

版本：0.2.0-draft。首轮 12 条各一次真实模型运行已完成，见 [逐例复核](live-baseline-review.md)；本文件保留原实验方案。

## 本次完成与剩余工作

已完成：只读业务资料调整、两个工具契约、独立评分标准、六个说明示例，以及 [首批 12 条开发案例规格](../../../eval/cases/campus-support-draft.md)、[可执行 JSON](../../../eval/cases/campus-support.json) 和 [静态逻辑审查](case-audit.md)。v0.12.0 已接入工具、Role、规则评分和 trace。

尚未完成：语义 Judge 接入与校准、独立人工复核、多次重复运行和 holdout。现有订单退款结果不能作为本场景基线。

## 最小 Role

已设置独立校园使用助手 Role：回答模拟校园平台使用问题，只能使用两个只读工具，不具备修改平台的能力；逐轮提供可信案例时间。`skills=()` 由场景配置和运行指纹确认。

无 Skill 不等于无 Role、无工具说明或无帮助文档。基础 Role 只放身份、范围及通用安全边界，不偷偷加入待比较的完整排查流程。不得加载订单退款 Skill。

## 实施和运行门槛

1. 实现契约及测试：正常/无匹配/超时、参数校验、案例状态隔离、发布时间过滤、09:42 不能看到 09:45 更新、恢复后查历史问题、相同对话复用证据。
2. 将审查示例扩展成可执行案例，增加时间边界、工具错误、资料不足、改写及多轮意图切换。冻结案例与资料版本后再运行；不预先承诺条数或通过率。
3. 独立实现场景评分，不把退款断言直接套用；语义评分未实现时只可生成待人工审查结果，不能宣布自动全通过。
4. 校准 Judge，人工复核部分 PASS 以及所有 REVIEW/争议 FAIL；保留自动和人工两套标签。
5. 使用实际配置的模型运行无 Skill 基线，保存每条 trace 和运行清单。重复次数在运行前固定；建议首轮验证后正式每例三次，单次试跑不称稳定结果。

## 基线清单与后续对照

记录模型/provider 配置（不记录密钥）、采样参数、Role 原文与哈希、空 Skill 列表、工具 schema/实现指纹、语料快照、案例与评分器/Judge 版本、重复次数、逐例结果与成本。token 缺失记 unavailable，不按零处理。

后续注入 Skill 时只改变明确声明的 Skill 内容，其余条件固定；使用新输出目录，保留旧 trace。若同期修订案例、文档或评分标准，应对两组统一重跑或重评分并说明，不混用口径。现有严格比较会拒绝 Skill 指纹变化，届时需显式受控差异协议或人工对照，不能关闭全部指纹检查。

开发案例可用于诊断；另留未参与 Skill 编写的案例验证泛化。报告任务通过率、待审核率、预算达标率及 Agent/Judge 分开的成本，不把单次差异全部归因于 Skill。
